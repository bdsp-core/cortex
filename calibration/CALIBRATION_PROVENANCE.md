### Data-entry-point note (combined_spike — IED-vs-benign fold)

The unified `spike` label_type carries 1,131,709 rows: 964,206 binary
yes/no rows (`0`/`1`, the sn1 spike-detection cohort) **plus** 167,503
spike-SUBTYPE rows (`ied, vertex wave, posts, wickets, bets, other`,
from the `centaur_2025_ied` source). **Decision 2026-05-18 (user):**
fold the Centaur-IED cohort in as a clinically meaningful binary
contrast rather than drop it — `value∈{0,1}→Y=int(value)`; otherwise
`Y = 1 if value=='ied' else 0` (IED vs the benign variants vertex
wave/POSTS/wickets/BETS/other). **All 1,131,709 spike rows are
retained — nothing dropped** (pos_rate 0.5869). This is a
**data-entry-point definition only**, recorded verbatim in
`combined_spike_meta.json` `provenance.source_label_filter`; no
carried-script methodology/statistical logic was altered (md5s in §2
unchanged). **Honest consequence:** mixing the harder IED-vs-benign
sub-task into spike lowers the spike Youden separation vs a
clean-binary-only fit (J 0.366 here vs ~0.63 for the {0,1}-only
variant) — an accepted, documented trade-off of the
nothing-lost decision (see §6 spike).

## 7. Methodology decisions (user-resolved 2026-05-18)

Two genuine forks surfaced during independent verification and were
**escalated to the user, not silently resolved**:

1. **Spike/Centaur-IED scope.** The first build excluded 167,503
   Centaur-IED spike-subtype rows (kept only clean {0,1}). User
   decision: **fold them in** as an IED-vs-benign binary contrast
   (nothing lost; §1). Implemented at the data entry point only;
   honest cost (spike J 0.63→0.37) documented in §6.
2. **D7 verdict.** The n=4 gold panel failed a within-CI
   reproduction for 4/6 IIIC. User decision: **re-scope D7** as a
   bootstrap CI-overlap + concordance consistency check with the n=4
   limitation stated explicitly (above) — not a tight-reproduction
   claim.

**No numerical/statistical logic, constant, model, or algorithm in any
carried reference script was changed.** All carried scripts remain
md5-identical to their sources (§2); both decisions are
data-entry-point / reporting-scope only.
